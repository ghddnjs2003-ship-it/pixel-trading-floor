## 1. AI 두뇌 — 무료 API 먼저, 로컬 Ollama는 나중에

`LLM_PROVIDER` 한 줄로 갈아 끼운다. 모두 OpenAI 형식(`/chat/completions`)을 쓰므로 코드는 그대로다.

| 제공자 | 필요한 키 | 무료 여부 | 기본 모델 |
|---|---|---|---|
| `groq` | `GROQ_API_KEY` | 무료 한도 | `llama-3.3-70b-versatile` |
| `gemini` | `GEMINI_API_KEY` | 무료 한도 | `gemini-3.5-flash-lite` |
| `cerebras` | `CEREBRAS_API_KEY` | 무료 한도 | `llama-3.3-70b` |
| `openrouter` | `OPENROUTER_API_KEY` | `:free` 모델 | `meta-llama/Llama-3.3-70B-Instruct:free` |
| `ollama` | **없음** | 로컬 GPU | `qwen2.5:7b-instruct` |
| `openai` / `xai` | 각각의 키 | 유료 | `gpt-4.1-mini` / `grok-3-mini` |

- `LLM_PROVIDER=auto`면 무료 제공자 → 유료 → Ollama 순으로 **키가 있는 첫 곳**을 쓴다.
- `LLM_MODEL`, `LLM_BASE_URL`로 모델·주소를 덮어쓸 수 있다(새 모델·자체 서버 대응).
- 어떤 제공자가 준비됐는지 확인: `python -m backend.providers`

**2026-11 실측 — Gemini 키 형식과 모델**
- `AQ.`로 시작하는 키도 정상 키다. 네이티브 API는 `x-goog-api-key` 헤더 또는 `?key=`, OpenAI 호환
  엔드포인트(`/v1beta/openai/chat/completions`)는 `Authorization: Bearer`로 통과한다(모델 목록 200).
- 문제는 모델 이름이었다: `gemini-2.0-flash`는 **신규 사용자에게 404**(폐기). `gemini-3.7/3.8-flash`는
  40~90초 무응답·503이 잦고, `gemini-3.5-flash-lite`(0.3초)와 `gemini-3.1-flash-lite`(3~7초)가 안정적이다.
- 그래서 기본 모델을 `gemini-3.5-flash-lite`로 바꾸고, 404면 `gemini-3.1-flash-lite →
  gemini-flash-lite-latest`로 넘어가는 대체 사슬(`fallbacks`)을 넣었다. 폐기는 앞으로도 반복되므로
  모델 이름을 코드에 하나만 두지 않는다.

```bash
cp backend/.env.example backend/.env      # 무료 키 하나만 채우면 된다
python -m backend.providers               # 키 유무 표
python -m backend.server                  # http://127.0.0.1:8765/index.html?engine=llm
```

13인 흐름은 호출 1회당 13번의 LLM 요청을 낸다. 무료 한도(관측: 분당 12~15회 부근에서 429, 몇 초 뒤 풀림)를
넘기지 않도록 429·5xx는 5초·10초 쉬고 다시 부른다. 무료 한도가 작은 제공자는 하루 몇 번이면
말라붙으니, `orchestrator`에 규칙 판정(v7)을 먼저 넣어 **AI가 볼 자료를 줄이고**,
실전 판단은 규칙 엔진이 하고 AI는 해설·예외 검토를 맡는 순서가 현실적이다(현재 코드가 그 구조).

## 2. AI 맥락 필터 (`ai_filter.py`) — 규칙이 선 자리를 Gemini가 다시 심사한다

**왜**: §4의 (6) 참고. 기계 규칙만으로는 시간봉·종목을 넘어 재현되는 플러스 조합이 없다. 후보1(30분 M1 ·
아시아 3ATR·4R·96봉)의 143건은 4R 도달 18건이 전체 +29.9R 중 +54.5R를 만들고, 83건은 전액 손절이다.
오라클로 최악 10%만 제거해도 평균 R이 +0.209 → +0.362로 올라 부트스트랩 95%가 0을 넘었다.
그래서 합격선은 **"7건 중 1건꼴로 손실 후보를 맞게 거르고, 4R 승자를 죽이지 않는 것"** 이다.

**무엇을 보내나** — 신호 봉(i)까지의 자료만으로 문맥을 만든다(미래 봉 참조 없음, 테스트로 고정).
- 최근 12봉 OHLC·거래량, 48·96봉 범위에서의 위치
- 1H 매물대 존(위/아래 3개, 거리 ATR) · BSL/SSL 유동성 거리 · **목표까지 경로의 장애물**(1R 이내 개수)
- EMA20/50·기울기, 4H EMA50 대비 위치, CCI(20), 볼린저 폭/10봉 평균, RSI14, 상대 거래량
- 거래 시점(UTC/KST·세션 경과), 손절·목표 가격과 ATR 배수 — 목표는 **체결 모형이 실제로 쓸 값**(후보1은 고정 4R)

**무엇을 받나** — `loss_prob`(목표 전에 손절로 끝날 확률 0~100)과 `{"decision":"PASS"|"REJECT","reason":"..."}`.
문턱(기본 60) 이상이면 REJECT. 모델이 확률을 빼먹으면 decision을 그대로 쓴다(지어내지 않는다).

**호출 관리** — 문맥 해시 캐시(`data/ai_cache.json`, git 무시) · 최소 간격 2초 · 429/503 백오프 ·
실행 1회 호출 예산(`--max-calls`) · 실패 시 기본 '통과'(매매를 멈추지 않고 `error`로 남긴다).

### 교차 검증 — 같은 필터, 다른 시장 (2026-11-19)

`python -m backend.cross_validation --market all --sample 60 --summary data/ai_filter_cross_validation_2026-11-19.json`

질문: **30분 BTC에서 통한 필터가 다른 시간봉·다른 종목에서도 통하는가.** 루브릭·문턱(60)·출력 형식은
30분 BTC에서 정한 그대로 두고, 문맥에 적히는 **종목·시간봉 이름만** 바꿔(예: `ETHUSDT 30분봉 단타 후보`)
BTC 15분·BTC 1시간·ETH 30분의 **최근 후보 60건씩**을 심사했다(gemini-3.5-flash-lite · 2초 간격 · 문맥 캐시 ·
결과는 `out/xval_*.json`에 심사 원장 포함, 요약만 커밋).

| 시장 (심사 구간) | 심사/REJECT | 체결 전→후 | 승률 | PF | 순손익 | 평균 R | MDD | 4R 승자 | 무작위 p |
|---|---|---|---|---|---|---|---|---|---|
| BTC 15분 · 96봉 (2026-03~11) | 60 / 36.7% | 57→36 | 35.1→36.1% | 0.90→0.91 | −4.37→−2.59% | −0.080→−0.080 | 14.3→15.8% | 4/6 | 0.506 |
| BTC 1시간 · 48봉 (2024-04~2026-11) | 60 / 23.3% | 59→45 | 35.6→33.3% | 0.78→**0.62** | −7.93→**−10.55%** | −0.130→**−0.240** | 13.6→11.3% | 1/3 | 0.854 |
| ETH 30분 · 96봉 (2025-09~2026-11) | 60 / 25.0% | 57→43 | 38.6→39.5% | 1.07→**1.22** | +2.58→**+6.16%** | +0.060→**+0.150** | 10.3→**8.7%** | 4/4 | 0.236 |

- **BTC 15분 — 중립.** 평균 R이 −0.080으로 똑같고 PF는 0.90→0.91. 최악 10% 5건 중 1건만 거부, 4R 승자 6건 중 2건을 죽였다.
- **BTC 1시간 — 나빠졌다.** 최악 10%를 하나도 거부하지 못했고(0/5) 4R 승자 3건 중 2건을 지웠다. PF 0.78→0.62, 무작위보다도 나쁘다(p=0.85).
- **ETH 30분 — 방향은 같다.** PF·순손익·MDD·평균 R이 모두 나아지고 4R 승자 4건을 그대로 살렸다(최악 10%는 40% 거부).
  그러나 표본 60건에서 p=0.236이라 **우연을 배제하지 못한다**.
- **구간을 앞 60% / 뒤 40%로 나누면**: BTC 15분은 앞에서 좋아지고(0.93→1.66) 뒤에서 무너지며(0.85→0.31),
  BTC 1시간은 뒤에서 무너지고(1.29→0.87), **ETH 30분은 앞에서 거의 그대로(1.68→1.63)다가 뒤에서 좋아진다**
  (PF 0.65→0.81 · 평균 R −0.25→−0.12 · 승률 32.1→36.8%). ETH의 개선은 최근 구간에서 나온 것이라 방향은
  맞지만, 그 구간 체결은 19건뿐이다.
- **한계**: 시장별로 문턱·루브릭을 다시 고르지 않았다(지시대로 60 고정 — 그게 이 실험의 조건이다). 표본 60건,
  시장별 구간·거래 수가 달라 30분 BTC 실측과 직접 비교는 아니다. 세 구간 모두 규칙 자체의 기준선이 약했고
  (BTC는 필터 후에도 마이너스), **필터는 지는 규칙을 이기게 만들지 못했다.**
- **결론**: 이 필터의 30분 BTC 성과는 **시장 일반 성질이 아니다**. 시간봉·종목을 바꾸면 따로 검증해야 하고,
  지금 근거로는 **30분 BTC 이외에 실돈을 걸 근거가 없다.**

## 3. v7 룰 엔진 (`strategy.py`) — 차트 라벨과 봉 단위로 맞춘다

트레이딩뷰 통합 지표 `indicators/double-s-mds-v7.pine`의 **판정 부분**을 파이썬으로 옮겼다.
라벨·박스 그리기는 옮기지 않았다(화면은 파인스크립트가 한다).

- 데이터: 바이비트·OKX·비트겟·바이낸스 공개 API(키 불필요) 또는 저장한 CSV/JSON. `auto`면 되는 곳부터.

### 실측 C — 구조 재설계 실험 (2026-11-19, 15분 45,000봉 = 2025-08~2026-11, 30분·1시간은 비트겟 장기 이력)

파라미터 미세조정이 아니라 **구조 축**을 넣고 다시 돌렸다. 코드에 반영된 축은 다음과 같다.

| 축 | 옵션 |
|---|---|
| 손절 | `stop_mode=structure`(스윕 극점·존 반대편) / `atr` + `stop_atr` (1.0~5.0 ATR, 실제 진입가 기준) |
| 목표 | `target_mode=signal`(반대편 유동성·1H 매물대 도달) / `r` + `target_r` (1~6R), `target_cap_r` |
| 청산 | `bracket` / `half_trail` / `trail`(목표 없이 ATR 추적) / `be_trail`(+N R에서 본전), `max_bars`(시간 손절) |
| 세션 | `session_filter` — UTC 기준 asia(00-08)·london(07-16)·ny(12-21)·london_ny·ny_open·outside_ln, `sessions`로 직접 지정 |
| 신호 선별 | `allow_kinds`(DS/M1) · `allow_sides` · `ds_labels`(거부/복귀) · `min_rvol` · `min_atr_pct`/`max_atr_pct`(변동성 구간) |
| 추세 | `use_htf_trend`(4H EMA50/200, M1) · `ds_htf_filter`(더블 S에도 동조 요구) |
| 시간봉 | 15 / 30 / 60분 (`--tf`, 15분봉에서 리샘플. 30·60분은 거래소 원본 봉으로도 대조) |

**(1) 비용이 1차 관문이다.** 거래당 리스크 1%일 때 손절 폭이 좁을수록 수수료·슬리피지가 R에서 차지하는 몫이 커진다(왕복 14bp ÷ 손절폭%). 1 ATR 손절(≈0.2%)이면 **건당 0.7R를 비용으로 내고**, 3 ATR(≈0.6%)이면 0.15R다. 실측에서도 1ATR 조합은 예외 없이 −99%(계좌 소멸)였고, 살아남은 조합은 모두 2.5 ATR 이상에서 나왔다.

**(2) 넓은 손절 + 큰 목표 + M1만.** 15분 180조합(손절 5종 × 목표 6종 × 청산 2종 × 신호 3종)에서 인샘플 플러스는 1개, 아웃샘플 플러스는 0개였다. 유일하게 인샘플이 플러스였던 `통합 3ATR·4R`(252건·PF 1.04)도 아웃샘플 −7.2%로 뒤집혔다. 살아남는 축은 분명하다 — **더블 S를 빼고 M1만**, 손절은 2.5~4 ATR, 목표는 3~6R.

**(3) 더블 S(스윕 반전)는 비용 전에도 엣지가 없다.** 30분 3.4년(2023-06~2026-11, 60,000봉)에서 더블 S만 + 4H EMA200 동조 + 3ATR·4R: 218건·PF 0.85·−24.2%, **비용 0에서도 −6.2%**. 1시간 7.4년에서도 같다. 반면 M1(존 돌파→리테스트)은 같은 조건에서 플러스가 나온다.

**(4) 살아남은 칸 — 30분 M1 · 아시아(00-08 UTC) · 3ATR · 4R · 96봉 시간손절**

| BTC 1시간, 30분 등가 기하(1.5ATR·48봉) | 7.4년 | −37.5% |

또 30분 격자 540칸 중 검색 구간 플러스 138칸·홀드아웃(2023-06~2025-08, 2.2년) 플러스 93칸이었고, **양쪽 모두 플러스인 칸은 24개 — 독립을 가정한 우연 기대치(0.26×0.17×540≈24)와 정확히 같다.** 칸 수를 세는 방식으로는 엣지를 확인할 수 없다는 뜻이다.

**(6) 결론.** 기계적 진입만으로는 **시간봉·종목을 넘어 재현되는 플러스 조합이 없다.** 30분 M1·아시아 칸 하나만 3.4년을 버티지만, 이것도 540칸 중 하나이고 다른 시장에서 재현되지 않아 실돈 근거로는 부족하다. "라벨이 서는 자리"는 정확하지만 그 자리에서 무조건 진입하는 것에는 엣지가 없다 — 이 지표를 쓰려면 **문맥 판단(상위 추세·존·거래량·뉴스·세션)** 이 필요하고, 그것이 다음 단계(AI 맥락 필터)의 근거다.

**다음 단계(AI 맥락 필터)가 넘어야 할 문턱 — 후보1의 거래 143건으로 계산**

- 수익 구조: 4R 목표 도달이 18건으로 **전체 +29.9R 중 +54.5R**를 만들고, 83건은 전액 손절(−83R), 44건은 시간 청산이다. 즉 상위 10% 거래가 전부를 만든다.
- 오라클(사후) 실험: 최악 10%(14건)만 제거하면 평균 R +0.209 → +0.362, 부트스트랩 95% 구간이 **[+0.029, +0.673]으로 0을 넘어간다**(15% 제거 시 +0.449, [+0.133, +0.796]).
- 그래서 요구치는 이렇다 — **"7건 중 1건꼴로 '이건 아니다'를 맞게 걸러내고 4R 승자를 죽이지 않으면"** 기계 규칙이 통계적으로 플러스가 된다. AI 두뇌(2번 단계)는 이 문턱을 목표로 붙이면 된다.

**미구현으로 남긴 축**: 다이버전스는 v7 파인에 없는 모듈이라 새로 만들어야 하고, 그 적용 대상인 더블 S가 비용 전에도 마이너스여서 우선순위에서 뺐다. 같은 이유로 더블 S의 라벨 종류·스윕 깊이 미세조정도 중단했다.

**(7) 과최적화 방지 장치(코드에 남김)**

- `lab.py` — 축 격자 + 인샘플(앞 60%)/아웃샘플(뒤 40%). 인샘플 15건 미만은 후보에서 제외.
- `verdict.py` — 후보 하나를 ① 분할 지점 3종 ② 분기·월별 ③ 비용 0/2/5/7bp ④ 부트스트랩 ⑤ **플라시보**(진입 시각 무작위)로 검증. 플라시보는 목표가 R 배수일 때만 유효하다(신호 목표는 원래 봉의 가격이라 시각을 옮기면 의미가 깨진다 — 코드가 건너뛴다).

**(8) AI 맥락 필터(3단계) — 오늘은 무료 한도에 막혔다**

후보는 15분·런던·4ATR·3R(체결 167건)로 정하고 `--tradable`(체결된 신호만 심사)로 돌렸다.
28건을 심사한 뒤 **Gemini 무료 한도 소진(HTTP 429, "exceeded your current quota")**으로 중단됐다.
(`--tradable`·`--tf-label`·`--prompt-version` 옵션은 이번에 추가 — 시간봉이 다른 후보를 같은 루브릭으로 심사하려면 필요하다.)
같은 명령을 한도가 풀린 뒤 다시 돌리면 캐시(`data/ai_cache.json`)에 남은 28건은 호출 없이 이어진다:

```bash
python3 -m backend.ai_filter --json data/btc_15m_45000.json --native --tradable --preset none \
  --tf-label 15분봉 --prompt-version "ctx-v2|BTCUSDT|15m|london4atr3r" \
  --base-p '{"stop_mode":"atr","stop_atr":4.0}' \
  --base-c '{"allow_kinds":["DS","M1"],"target_mode":"r","target_r":3.0,"session_filter":"london"}' \
  --json-out out/ai_filter_15m_london4atr3r.json
```

한편 "AI가 걸러야 할 몫"은 오라클로 계산해 두었다(사후에 최악 거래만 제거):
15분 후보의 평균 R은 +0.364, **최악 5%(8건)를 정확히 제거하면 +0.444 [+0.145, +0.744]**로 95% 구간이 0을 넘는다.
1시간 후보는 최악 5% 제거로 +0.324 [−0.145, +0.794] — 여전히 0을 걸친다.
즉 필터는 15분 후보에서 **"20건 중 1건꼴로 손실을 맞게 거르고 3R 승자를 죽이지 않는"** 수준을 넘어야 한다.

**(9) 결론**

- **5분: 실전 후보 없음.** 비용이 좁은 손절을 전부 지우고, 살아남는 칸은 5분 규칙이 아니다(12ATR·연 46~95건).
- **15분: 가장 좋아 보이는 칸 하나(+78%, 플라시보 100)가 있지만 다른 시간봉·종목에서 재현되지 않는다.**
- **1시간: 7.3년에 141건·PF 1.25로 균형은 좋지만 롱에만 기대고 연 19건이다.**
- **4시간: 통과 칸 수가 우연과 같다.**
- **MTF: 구조는 완성했고 테스트로 고정했지만, 성적은 방향 베팅이다.**
- 실전 후보로 추릴 시간봉 세트는 **없음**. 굳이 하나를 고르라면 30분 M1·아시아(기존 후보1)가 유일하게 3.4년을 버틴 칸이고,
  그것도 540칸 중 하나다(§4 실측 C).

요약 수치 전체: `data/mtf_exploration_2026-11-19.json`(격자 통계·후보·교차 검증·롤링 창).

### 과최적화 경계

- 조합을 30개 넘게 돌렸으니 그중 하나쯤 잘 나오는 것은 당연하다. 그래서 (a) 체결 10건 미만 조합은 표에서 제외하고 (b) 인샘플에서 고른 조합의 아웃샘플 성적을 함께 냈고 (c) 비용·체결 가정을 모든 조합에 똑같이 적용했다.
- 인샘플 상위 조합이 아웃샘플에서 뒤집히는 경우가 많았다(예: `목표 2.5R 더블S` IS −9.5% → OS −24.3%). 조합 선택 자체가 과최적화라는 뜻이다.

## 6. 실시간 모의매매 루프 (`paper_loop.py`)

지금 장에서 후보1(30분 M1 · 아시아 · 3ATR · 4R · 96봉)이 서면 **AI 판정과 함께 모의 진입·청산을 기록**한다.
주문은 내지 않고 거래소 키도 쓰지 않는다 — 공개 시세 + 규칙 + AI 판정만 남긴다.

```bash
python -m backend.paper_loop --once                    # 1회(스케줄러·cron 연동용)
python -m backend.paper_loop --loop --interval 300     # 5분마다 계속
python -m backend.paper_loop --status                  # 현재 상태·최근 로그
python -m backend.paper_loop --reset                   # 모의 계좌 초기화
curl -s http://127.0.0.1:8765/api/paper                # GET — 상태·킬스위치·최근 로그
curl -s -X POST http://127.0.0.1:8765/api/paper/tick   # POST — 1회 스캔(주문 없음)
```

- **한 번의 스캔(tick)**: ① 공개 API(OKX·비트겟·바이낸스 폴백)로 최신 30분봉을 받아 **진행 중인 봉을 버리고**
  확정 봉만 쓴다(그 봉의 시가를 '다음 봉 시가'로 진입가에 쓴다 — 추격 금지 규칙 그대로) ② 마지막 확정 봉에 M1 후보가
  서면 세션(아시아) → 킬스위치 → AI 맥락 필터 순으로 통과시킨다 ③ 열린 포지션은 새로 확정된 봉마다 손절·4R 목표·
  96봉 시간 청산을 판정한다(같은 봉은 두 번 평가하지 않는다 — `last_bar_time`·`signals_seen`).
- **기록**: `data/paper_state.json`(현재 포지션·누적 통계·킬스위치 상태) · `data/paper_log.jsonl`(매 스캔의
  판정·AI PASS/REJECT 사유·청산 내역·누적 손익). 둘 다 실행 산출물이라 git에서 제외한다.
- **AI가 REJECT면 진입하지 않고 그 사유를 로그에 남긴다.** AI 장애는 통과(규칙만)로 기록하고 `error`를 남긴다 —
  매매를 멈추지 않는다(`ai_filter`의 `on_error` 정책 그대로).
- **키 격리**: 상태·로그에 API 키·프롬프트 원문이 들어가지 않는다(테스트 `test_logs_never_contain_api_key`).
- **첫 실측(2026-11-19 14:49 KST)**: OKX 30분봉 2,999봉 · 마지막 확정 봉 05:00 UTC · 신호 없음(HOLD) ·
  자본 10,000 USDT · 진입 가능(정상). 신호 패스는 커밋된 15분봉 픽스처를 30분봉으로 묶어
  실제 엔진이 세운 M1 자리로 검증했다(진입가 = 다음 봉 시가, 손절 3ATR, 목표 4R, 리스크 1%).

## 9. 다중 시간봉(`mtf.py`) — 큰 봉 방향·매물대 + 작은 봉 정밀 진입

§4 실측 D의 결과까지 담은 모듈. `strategy.py`의 v7 엔진(하위 봉)과 `MTFParams`(상위 봉 규칙)를 분리했다.

| 층 | 옵션 |
|---|---|
| `htf_minutes` | 60(1시간) · 240(4시간) |
| `htf_mode` | `ema` · `ema200` · `breakout` · `zone` · `ema_zone` |
| `allow_kinds` | `M1` · `DS` · 둘 다 (하위 봉 트리거) |
| `ltf_zone_dist_atr` | >0이면 하위 신호가 상위 매물대에서 그 거리(HTF ATR) 안일 때만 |
| `stop_mode` | `ltf_atr` · `htf_atr`(→ `stop_dist`) · `htf_zone` |
| `target_mode` | `r`(+`target_r`) · `htf_zone`(반대편 매물대) |

- 시점 규칙: LTF 봉 i가 끝나고 신호, i+1 시가 진입. 상위 봉은 `htf[k].t + htf_minutes <= candles[i].t`인 마지막 봉만 본다.
- 함수: `htf_frame()`(상위 상태) · `mtf_signals()`(편향·손절·목표 적용) · `run_mtf()`(체결) · `report()`(분할·비용·부트스트랩·플라시보) · `run_rows()`(격자).
- `backtest.simulate`는 신호의 `stop_dist`(가격 거리)를 받아 **실제 진입가** 기준으로 손절을 잡는다(상위 ATR 손절용).

```bash
python -m backend.mtf --json data/btc_15m_45000.json --htf 240 --top 20 --json-out out/mtf_15m_4h.json
python -m backend.lab --json data/btc_5m_105000.json  --native --tf 5   --preset short   # 5분 전용
python -m backend.lab --json data/btc_4h_16200.json   --native --tf 240 --preset long    # 4시간 전용
python -m backend.verdict --json data/btc_4h_16200.json --native --tf 240 \
  --base-p '{"stop_mode":"atr","stop_atr":4.0,"box_tf_minutes":240}' \
  --base-c '{"allow_kinds":["M1"],"target_mode":"r","target_r":6.0}'
```

AI 필터 CLI에 이번에 붙은 옵션: `--tradable`(체결된 신호만 심사 — 포지션 중복 신호에 호출을 쓰지 않는다) ·
`--tf-label` · `--prompt-version`(시간봉·시장별로 캐시를 가른다). `--tf`는 5·240분까지 받는다.
