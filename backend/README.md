## 1. AI 두뇌 — 무료 API 먼저, 로컬 Ollama는 나중에

`LLM_PROVIDER` 한 줄로 갈아 끼운다. 모두 OpenAI 형식(`/chat/completions`)을 쓰므로 코드는 그대로다.

| 제공자 | 필요한 키 | 무료 여부 | 기본 모델 |
|---|---|---|---|
| `groq` | `GROQ_API_KEY` | 무료 한도 | `llama-3.3-70b-versatile` |
| `gemini` | `GEMINI_API_KEY` | 무료 한도 | `gemini-3.5-flash-lite` |
| `cerebras` | `CEREBRAS_API_KEY` | 무료 한도 | `llama-3.3-70b` |
| `openrouter` | `OPENROUTER_API_KEY` | `:free` 모델 | `meta-llama/Llama-3.3-70B-Instruct:free` |
| `ollama` | **없음** | 로컬 GPU | `qwen2.5:7b-instruct` |
| `openai` / `xai` | 각각의 키 | 유료 | `gpt-4.1-mini` / `grok-3-mini` |

- `LLM_PROVIDER=auto`면 무료 제공자 → 유료 → Ollama 순으로 **키가 있는 첫 곳**을 쓴다.
- `LLM_MODEL`, `LLM_BASE_URL`로 모델·주소를 덮어쓸 수 있다(새 모델·자체 서버 대응).
- 어떤 제공자가 준비됐는지 확인: `python -m backend.providers`

**2026-11 실측 — Gemini 키 형식과 모델**
- `AQ.`로 시작하는 키도 정상 키다. 네이티브 API는 `x-goog-api-key` 헤더 또는 `?key=`, OpenAI 호환
  엔드포인트(`/v1beta/openai/chat/completions`)는 `Authorization: Bearer`로 통과한다(모델 목록 200).
- 문제는 모델 이름이었다: `gemini-2.0-flash`는 **신규 사용자에게 404**(폐기). `gemini-3.7/3.8-flash`는
  40~90초 무응답·503이 잦고, `gemini-3.5-flash-lite`(0.3초)와 `gemini-3.1-flash-lite`(3~7초)가 안정적이다.
- 그래서 기본 모델을 `gemini-3.5-flash-lite`로 바꾸고, 404면 `gemini-3.1-flash-lite →
  gemini-flash-lite-latest`로 넘어가는 대체 사슬(`fallbacks`)을 넣었다. 폐기는 앞으로도 반복되므로
  모델 이름을 코드에 하나만 두지 않는다.

```bash
cp backend/.env.example backend/.env      # 무료 키 하나만 채우면 된다
python -m backend.providers               # 키 유무 표
python -m backend.server                  # http://127.0.0.1:8765/index.html?engine=llm
```

13인 흐름은 호출 1회당 13번의 LLM 요청을 낸다. 무료 한도(관측: 분당 12~15회 부근에서 429, 몇 초 뒤 풀림)를
넘기지 않도록 429·5xx는 5초·10초 쉬고 다시 부른다. 무료 한도가 작은 제공자는 하루 몇 번이면
말라붙으니, `orchestrator`에 규칙 판정(v7)을 먼저 넣어 **AI가 볼 자료를 줄이고**,
실전 판단은 규칙 엔진이 하고 AI는 해설·예외 검토를 맡는 순서가 현실적이다(현재 코드가 그 구조).

## 2. AI 맥락 필터 (`ai_filter.py`) — 규칙이 선 자리를 Gemini가 다시 심사한다

**왜**: §4의 (6) 참고. 기계 규칙만으로는 시간봉·종목을 넘어 재현되는 플러스 조합이 없다. 후보1(30분 M1 ·
아시아 3ATR·4R·96봉)의 143건은 4R 도달 18건이 전체 +29.9R 중 +54.5R를 만들고, 83건은 전액 손절이다.
오라클로 최악 10%만 제거해도 평균 R이 +0.209 → +0.362로 올라 부트스트랩 95%가 0을 넘었다.
그래서 합격선은 **"7건 중 1건꼴로 손실 후보를 맞게 거르고, 4R 승자를 죽이지 않는 것"** 이다.

**무엇을 보내나** — 신호 봉(i)까지의 자료만으로 문맥을 만든다(미래 봉 참조 없음, 테스트로 고정).
- 최근 12봉 OHLC·거래량, 48·96봉 범위에서의 위치
- 1H 매물대 존(위/아래 3개, 거리 ATR) · BSL/SSL 유동성 거리 · **목표까지 경로의 장애물**(1R 이내 개수)
- EMA20/50·기울기, 4H EMA50 대비 위치, CCI(20), 볼린저 폭/10봉 평균, RSI14, 상대 거래량
- 거래 시점(UTC/KST·세션 경과), 손절·목표 가격과 ATR 배수 — 목표는 **체결 모형이 실제로 쓸 값**(후보1은 고정 4R)

**무엇을 받나** — `loss_prob`(목표 전에 손절로 끝날 확률 0~100)과 `{"decision":"PASS"|"REJECT","reason":"..."}`.
문턱(기본 60) 이상이면 REJECT. 모델이 확률을 빼먹으면 decision을 그대로 쓴다(지어내지 않는다).

**호출 관리** — 문맥 해시 캐시(`data/ai_cache.json`, git 무시) · 최소 간격 2초 · 429/503 백오프 ·
실행 1회 호출 예산(`--max-calls`) · 실패 시 기본 '통과'(매매를 멈추지 않고 `error`로 남긴다).

## 3. v7 룰 엔진 (`strategy.py`) — 차트 라벨과 봉 단위로 맞춘다

트레이딩뷰 통합 지표 `indicators/double-s-mds-v7.pine`의 **판정 부분**을 파이썬으로 옮겼다.
라벨·박스 그리기는 옮기지 않았다(화면은 파인스크립트가 한다).

**2026-11-19 재이식.** 초안이 파인과 달랐던 곳을 실제 차트 라벨과 대조해 고쳤다.

| 항목 | 초안(폐기) | v7 파인 그대로(현재) |
|---|---|---|
| 스윙 레벨 | 24봉 2봉 프랙털, 가격 위/아래로 필터 | `ta.pivothigh/low(10,10)` + 배열 최대 5개(소모된 레벨도 자리를 차지) |
| BOS | 회복 봉이 직전 봉 구조를 깨야 함(기본 ON) | **없음** — 파인에 없는 조건이라 신호를 지우고 있었다 |
| 매물대 존 | 거래량 프로파일(192봉·60칸) | **1시간봉 몸통 피벗(좌우 5) ± 0.30 × 1H ATR**, 방향별 3개 |
| 존 확정 | 4봉 나이 | 이탈 + 4봉, 또는 60봉(파인 `boxExitBuf`·`maxBoxBars`) |
| M1 리테스트 | 15봉, 첫 리테스트 | 8봉, 0.15 ATR 터치, 15봉 쿨타임, 방향별 연속 2회 제한 |
| 볼린저 | 종가 표준편차 폭 비교 | `(상단-하단)/중심×100` 폭이 **10봉 평균보다 큰지** |
| 손익비 | 1.5R 미만 신호 폐기 | 라벨은 그대로 두고, 목표만 반대편 유동성→1.5R 대체 |

- 스윕: 깊이 0.05~1.60 ATR + 같은 봉 거부(종가 복귀) 또는 다음 봉 복귀, 0.5 ATR 완전 돌파 시 레벨 폐기
- 추세 필터: EMA20/EMA50 + 3연속 음봉·양봉 (파인 `isStrongUp/isStrongDown`)
- M1: 존 경계를 거래량 1.15배로 종가 돌파 → 첫 리테스트에서 경계 유지 + CCI(20, hlc3) 방향 + 볼린저 확장 + 리테스트 거래량 감소
- 손절: M1은 존 반대편 경계(파인 `m1Stop`), 더블 S는 스윕 극점 밖 0.15 ATR(CES 룰 — 파인에 없는 값)
- 신호는 i번 봉이 끝난 뒤 확정, 진입은 i+1 시가(미래 참조 없음 — 테스트로 고정)

## 4. 백테스트와 조합 탐색 (`backtest.py` · `explore.py`)

- 데이터: 바이비트·OKX·비트겟·바이낸스 공개 API(키 불필요) 또는 저장한 CSV/JSON. `auto`면 되는 곳부터.
- 체결: 다음 봉 시가, 손절·목표가 같은 봉에서 둘 다 닿으면 **손절 우선**(비관), 편도 수수료 5bp·슬리피지 2bp 기본.
- 청산: `--exit-mode bracket`(전량 목표) · `half_trail`(1R 절반 익절 + 본전 + ATR 추적) · `trail`(목표 없이 ATR 추적) · `be_trail`(+N R에서 본전 후 추적). `--max-bars`는 시간 손절.
- 손절: `--stop-mode structure|atr` + `--stop-atr`(실제 진입가 기준 ATR 배수). 목표: `--target r:2.0` · `--target-cap-r`, 더블 S는 `--ds-target liq|zone|r`.
- 진입 제한: `--session off|asia|london|ny|ny_open|london_ny|outside_ln`(UTC), `--allow DS,M1`, `--htf off|ema50|ema200`. 옵션 전체는 `--help`.
- 지표: 체결 수·승률·평균 R·PF·순손익·최대낙폭·최장 연속손실·종류별.

### 실측 C — 구조 재설계 실험 (2026-11-19, 15분 45,000봉 = 2025-08~2026-11, 30분·1시간은 비트겟 장기 이력)

파라미터 미세조정이 아니라 **구조 축**을 넣고 다시 돌렸다. 코드에 반영된 축은 다음과 같다.

| 축 | 옵션 |
|---|---|
| 손절 | `stop_mode=structure`(스윕 극점·존 반대편) / `atr` + `stop_atr` (1.0~5.0 ATR, 실제 진입가 기준) |
| 목표 | `target_mode=signal`(반대편 유동성·1H 매물대 도달) / `r` + `target_r` (1~6R), `target_cap_r` |
| 청산 | `bracket` / `half_trail` / `trail`(목표 없이 ATR 추적) / `be_trail`(+N R에서 본전), `max_bars`(시간 손절) |
| 세션 | `session_filter` — UTC 기준 asia(00-08)·london(07-16)·ny(12-21)·london_ny·ny_open·outside_ln, `sessions`로 직접 지정 |
| 신호 선별 | `allow_kinds`(DS/M1) · `allow_sides` · `ds_labels`(거부/복귀) · `min_rvol` · `min_atr_pct`/`max_atr_pct`(변동성 구간) |
| 추세 | `use_htf_trend`(4H EMA50/200, M1) · `ds_htf_filter`(더블 S에도 동조 요구) |
| 시간봉 | 15 / 30 / 60분 (`--tf`, 15분봉에서 리샘플. 30·60분은 거래소 원본 봉으로도 대조) |

**(1) 비용이 1차 관문이다.** 거래당 리스크 1%일 때 손절 폭이 좁을수록 수수료·슬리피지가 R에서 차지하는 몫이 커진다(왕복 14bp ÷ 손절폭%). 1 ATR 손절(≈0.2%)이면 **건당 0.7R를 비용으로 내고**, 3 ATR(≈0.6%)이면 0.15R다. 실측에서도 1ATR 조합은 예외 없이 −99%(계좌 소멸)였고, 살아남은 조합은 모두 2.5 ATR 이상에서 나왔다.

**(2) 넓은 손절 + 큰 목표 + M1만.** 15분 180조합(손절 5종 × 목표 6종 × 청산 2종 × 신호 3종)에서 인샘플 플러스는 1개, 아웃샘플 플러스는 0개였다. 유일하게 인샘플이 플러스였던 `통합 3ATR·4R`(252건·PF 1.04)도 아웃샘플 −7.2%로 뒤집혔다. 살아남는 축은 분명하다 — **더블 S를 빼고 M1만**, 손절은 2.5~4 ATR, 목표는 3~6R.

**(3) 더블 S(스윕 반전)는 비용 전에도 엣지가 없다.** 30분 3.4년(2023-06~2026-11, 60,000봉)에서 더블 S만 + 4H EMA200 동조 + 3ATR·4R: 218건·PF 0.85·−24.2%, **비용 0에서도 −6.2%**. 1시간 7.4년에서도 같다. 반면 M1(존 돌파→리테스트)은 같은 조건에서 플러스가 나온다.

**(4) 살아남은 칸 — 30분 M1 · 아시아(00-08 UTC) · 3ATR · 4R · 96봉 시간손절**

| 구간 | 체결 | 승률 | PF | 순손익 | MDD |
|---|---|---|---|---|---|
| 3.4년 전체 (2023-06~2026-11) | 143 | 37.1% | 1.29 | **+31.8%** | 12.2% |
| 앞 60% (인샘플) | 82 | — | 1.27 | +16.3% | |
| 뒤 40% (아웃샘플) | 61 | — | 1.31 | +15.4% | |
| 50/50 분할 | 64 / 79 | | 1.24 / 1.32 | +11.3% / +20.4% | |
| 70/30 분할 | 98 / 45 | | 1.14 / 1.61 | +10.8% / +21.0% | |

- 분할 지점을 50·60·70%로 바꿔도 양쪽이 모두 플러스다. 분기 15개 중 10개 플러스, 최악 분기 −8.7%.
- 비용 민감도: 수수료 0bp +50.9% · 2bp +43.0% · 5bp +31.8% · 7bp +24.8% (왕복 14bp 가정에서도 남는다).
- 부트스트랩 평균 R +0.209, 95% 구간 [−0.093, +0.492] — 0을 살짝 걸친다.
- **플라시보**(같은 손절·목표·세션으로 진입 시각만 무작위): 실제 +31.8%, 대조군 중앙 −19.7%·상위 5% +2.9% → 백분위 100. 아웃샘플도 +15.4% vs 대조군 상위 5% +8.2%.

**(5) 그러나 재현되지 않는다.** 같은 규칙을 다른 시간봉·다른 종목에 넣으면 무너진다.

| 시장 | 기간 | 결과 |
|---|---|---|
| BTC 15분 (같은 기간) | 16개월 | −9.6% (PF 0.87) |

또 30분 격자 540칸 중 검색 구간 플러스 138칸·홀드아웃(2023-06~2025-08, 2.2년) 플러스 93칸이었고, **양쪽 모두 플러스인 칸은 24개 — 독립을 가정한 우연 기대치(0.26×0.17×540≈24)와 정확히 같다.** 칸 수를 세는 방식으로는 엣지를 확인할 수 없다는 뜻이다.

**(6) 결론.** 기계적 진입만으로는 **시간봉·종목을 넘어 재현되는 플러스 조합이 없다.** 30분 M1·아시아 칸 하나만 3.4년을 버티지만, 이것도 540칸 중 하나이고 다른 시장에서 재현되지 않아 실돈 근거로는 부족하다. "라벨이 서는 자리"는 정확하지만 그 자리에서 무조건 진입하는 것에는 엣지가 없다 — 이 지표를 쓰려면 **문맥 판단(상위 추세·존·거래량·뉴스·세션)** 이 필요하고, 그것이 다음 단계(AI 맥락 필터)의 근거다.

**다음 단계(AI 맥락 필터)가 넘어야 할 문턱 — 후보1의 거래 143건으로 계산**

- 수익 구조: 4R 목표 도달이 18건으로 **전체 +29.9R 중 +54.5R**를 만들고, 83건은 전액 손절(−83R), 44건은 시간 청산이다. 즉 상위 10% 거래가 전부를 만든다.
- 오라클(사후) 실험: 최악 10%(14건)만 제거하면 평균 R +0.209 → +0.362, 부트스트랩 95% 구간이 **[+0.029, +0.673]으로 0을 넘어간다**(15% 제거 시 +0.449, [+0.133, +0.796]).
- 그래서 요구치는 이렇다 — **"7건 중 1건꼴로 '이건 아니다'를 맞게 걸러내고 4R 승자를 죽이지 않으면"** 기계 규칙이 통계적으로 플러스가 된다. AI 두뇌(2번 단계)는 이 문턱을 목표로 붙이면 된다.

**미구현으로 남긴 축**: 다이버전스는 v7 파인에 없는 모듈이라 새로 만들어야 하고, 그 적용 대상인 더블 S가 비용 전에도 마이너스여서 우선순위에서 뺐다. 같은 이유로 더블 S의 라벨 종류·스윕 깊이 미세조정도 중단했다.

**(7) 과최적화 방지 장치(코드에 남김)**

- `lab.py` — 축 격자 + 인샘플(앞 60%)/아웃샘플(뒤 40%). 인샘플 15건 미만은 후보에서 제외.
- `verdict.py` — 후보 하나를 ① 분할 지점 3종 ② 분기·월별 ③ 비용 0/2/5/7bp ④ 부트스트랩 ⑤ **플라시보**(진입 시각 무작위)로 검증. 플라시보는 목표가 R 배수일 때만 유효하다(신호 목표는 원래 봉의 가격이라 시각을 옮기면 의미가 깨진다 — 코드가 건너뛴다).

### 과최적화 경계

- 조합을 30개 넘게 돌렸으니 그중 하나쯤 잘 나오는 것은 당연하다. 그래서 (a) 체결 10건 미만 조합은 표에서 제외하고 (b) 인샘플에서 고른 조합의 아웃샘플 성적을 함께 냈고 (c) 비용·체결 가정을 모든 조합에 똑같이 적용했다.
- 인샘플 상위 조합이 아웃샘플에서 뒤집히는 경우가 많았다(예: `목표 2.5R 더블S` IS −9.5% → OS −24.3%). 조합 선택 자체가 과최적화라는 뜻이다.

AI·규칙과 분리된 정지 장치. 주문은 내지 않고 "지금 진입해도 되나"만 답한다.

| 규칙 | 기본값 | 동작 |
|---|---|---|
| 일일 최대 손실 | 계좌의 3% | 당일 중단 |

| 수동 정지 | — | 직접 풀기 전까지 진입 금지 |

  거래소 키가 먼저 필요하다.
- **5분봉 라이브 판정의 존**: orchestrator는 5분봉 144개(12시간)만 받는다. 1시간봉 몸통 피벗은
  최소 11시간 + 확인 1시간이 필요해 그 창에서는 존이 거의 서지 않는다. 라이브에서 M1까지 보려면
  수집 봉 수를 1,000개 이상으로 늘려야 한다.
